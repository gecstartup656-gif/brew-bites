Build "The Brew Bits" — a fast, offline-capable cafe billing/POS web app.

STACK: React + TypeScript + Tailwind. No Supabase/cloud DB. Use browser IndexedDB (via localForage) as the only persistence layer, structured as JSON collections mirroring: settings, categories, menu, currentDay, dailyLogs. Provide JSON export/import for backup/restore. App must work fully offline after first load (no external APIs, no CDN-dependent functionality, no online fonts).

DATA MODELS (TS interfaces):

Category { id, name }

MenuItem { id, name, categoryId, price, tax, available }

BillItem { itemId, name, price, qty, total }

Bill { id, billNumber, items: BillItem[], subtotal, discount, tax, total, paymentMethod: 'cash'|'upi'|'card', createdAt }

CurrentDay { date, billNumber, bills: Bill[] }

DailyLog { date, bills: Bill[], summary: { sales, billCount, avgBill, cash, upi, card, topItems } }

Settings { cafeName, address, phone, gst, currency, businessDayStart }

NAV: Dashboard | Billing | Menu | Bills | Reports | Settings

BILLING (core screen, keyboard-first, most important):

Search bar + category chips filter the menu grid

Click item → add to cart; qty +/- controls; remove line

Live subtotal / discount / tax / total

Payment toggle: Cash / UPI / Card

"Generate Bill" → assign sequential billNumber, write to IndexedDB immediately, THEN show print-friendly receipt — never lose a bill if printing fails

"Clear" button to reset cart

Large buttons, minimal clicks, empty-cart / invalid-qty guards with friendly error messages

RECEIPT: thermal-style printable page (narrow width look), shows cafe header (name/address/phone), bill #, date/time, line items (name, qty x price, total), subtotal/discount/tax/total, payment method, "Thank You" footer. Use window.print() with dedicated print CSS.

MENU MANAGEMENT: CRUD categories (block delete if items reference it) + items (name, price, tax, category, available toggle, search). Never hard-delete historical bill data.

BILLS / HISTORY: today's bills + browse past daily logs; search by bill number or date; view and reprint any past bill; show payment method and total.

DASHBOARD: today's sales, bill count, avg bill value, cash/UPI/card totals, top 5 selling items, last-7-days sales trend chart (recharts). All figures computed from stored JSON, no external calls.

REPORTS: daily / weekly / monthly summaries computed from dailyLogs + currentDay; export as JSON; printable report view.

SETTINGS: cafe name, address, phone, GST/tax info, currency, business-day-start time — persisted to the settings store.

CLOSE DAY: finalize currentDay → append to dailyLogs (keyed by date) → generate summary → reset currentDay with billNumber back to 1 for a fresh business day. On app load, auto-detect if a new business day has started (based on businessDayStart, not a rigid 24h clock) and prompt to close if needed.

BACKUP/RESTORE: "Backup Now" exports the full IndexedDB state as a timestamped JSON file download; "Restore Backup" imports a JSON file and asks for confirmation before overwriting anything — never silently overwrite.

ERROR HANDLING: corrupted/missing storage fallback, duplicate bill-number prevention, invalid price/quantity guards, backend-unavailable equivalent (storage-write-failed) messaging — all as clear, non-technical toasts/messages. Never silently discard billing data.

UI: clean professional POS look, large tap targets, responsive desktop-first layout, simple top nav, no over-engineering.
